# Як зберігати свою роботу в GitHub

Коротка інструкція для всієї команди. Робимо все в **GitHub Desktop**. Хто працює в Claude Code, може просто попросити Claude зробити ці кроки.

**Кілька слів, які тут трапляються:**
- **Репозиторій** — спільна папка проєкту на GitHub.
- **Clone** — копія репозиторію у тебе на комп'ютері, яка пам'ятає, звідки вона.
- **Гілка (branch)** — твоя окрема «чернетка» проєкту. Поки ти в ній, ти нічого не ламаєш іншим.
- **Commit** — збереження шматка роботи з коротким описом.
- **Push** — надіслати свої коміти на GitHub.
- **Pull Request (PR)** — запит «додай зміни з моєї гілки в `main`».
- **Merge** — злиття: зміни з PR потрапляють у `main`, і всі їх отримують.
- **`main`** — головна гілка, з якої збирається гра. У ній завжди має бути робоча версія.

---

## Один раз на початку

1. Прийми запрошення в репозиторій: лист від GitHub або github.com/notifications → **Accept invitation**.
2. GitHub Desktop → **File → Clone repository** → вибери `moon-company-iasasus` → **Clone**.
   Не роби **fork**: він потрібен тільки людям без доступу.
3. Unity Hub → **Add → Add project from disk** → вибери папку, куди склонувався репозиторій. Перший імпорт триває 5–15 хв.

---

## На кожну задачу

1. **Оновись.** Current Branch → **main** → **Fetch origin** → **Pull origin**.
   (У Claude Code: `/sync`.)
2. **Створи гілку.** Current Branch → **New Branch** → назва `NN-роль/що-робиш`, наприклад `03-sim/greenhouse` → **Create Branch**.
   Переконайся, що вгорі написано назву твоєї гілки, а не `main`.
3. **Працюй** у Unity тільки у своїй зоні (див. `CLAUDE.md`, таблиця «Структура і власники»).
4. **Коміть часто.** Щось запрацювало → у GitHub Desktop зліва внизу напиши короткий опис → **Commit to `<твоя гілка>`**.
   Завжди став галочки і на файли, і на їхні `.meta`.
5. **Push.** Натисни **Push origin** (або **Publish branch**, якщо гілка нова).
6. **Створи PR.** Натисни **Create Pull Request** → відкриється сайт → **Create pull request**.
7. **Перевір перед злиттям:**
   - у Unity немає червоних помилок у вікні Console;
   - твої тести зелені (Window → General → Test Runner → EditMode → Run All);
   - у PR змінено тільки файли з твоєї зони (вкладка **Files changed**).
8. **Злий сам.** На сторінці PR → **Merge pull request** → **Confirm merge**.
9. **Напиши в чат команди**, що ти злив, наприклад «Злив теплицю, оновлюйтесь».
10. **Повернись на `main`:** Current Branch → **main** → **Pull origin**. Наступна задача починається з кроку 1.

---

## Коли зливає не автор, а техлід

Не зливай сам, а напиши техліду в чат з посиланням на PR, якщо в PR є:
- сцени `.unity` або префаби `.prefab`;
- файли з `Scripts/Core/`;
- зміни в `CLAUDE.md`.

## Якщо щось пішло не так

| Що бачиш | Що робити |
|---|---|
| На сторінці PR: «This branch has conflicts» | Нічого не натискай. Конфлікт — це коли двоє змінили той самий файл. Клич техліда. |
| GitHub Desktop: «rejected» або «Pull origin first» під час push | Натисни **Pull origin**, потім знову **Push origin**. |
| Випадково працював у `main` | **Не коміть.** Current Branch → **New Branch**: GitHub Desktop запропонує перенести твої зміни в нову гілку → **Bring my changes**. |
| Після злиття гра перестала працювати | Відкрий свій PR на сайті → кнопка **Revert** → злий PR, який вона створить. Напиши в чат. |

**Ніколи** не використовуй `--force` і не видаляй файли `.meta`.
